## Track token usage

TensorZero automatically collects, normalizes, and reports token usage for every inference.

The normalized figures follow the OpenAI behavior (e.g. output tokens include reasoning tokens).
If you're using [Inference Caching](/gateway/guides/inference-caching), the gateway will report usage as 0 for cached inferences.

If you need additional usage information from model providers (e.g. prompt caching), you can enable `include_raw_usage` in the inference request.
In that case, the gateway will additionally report provider-specific usage fields without preprocessing.

You can browse usage data for individual inferences as well as aggregated usage statistics per model provider in the TensorZero UI.
Send `x-tensorzero-tags: env=prod,team=ml` (or `tensorzero::tags` in the JSON body) to label traffic; the Inferences list and Models request-mix table can filter and group by those tags.
You can also [enforce custom rate limits](/operations/enforce-custom-rate-limits) based on token usage.

## Track cost

TensorZero can compute and report cost for LLM inferences with additional configuration.

<Tip>

You can find a [complete runnable example](https://github.com/tensorzero/tensorzero/tree/main/examples/docs/guides/operations/track-usage-and-cost) of this guide on GitHub.

</Tip>

### Configure cost tracking for model providers

You can configure cost information by adding a `cost` section to the model provider configuration:

```toml title="tensorzero.toml"
[models.gpt-5.providers.openai]
type = "openai"
model_name = "gpt-5"
cost = [
  { pointer = "/usage/prompt_tokens", cost_per_million = 1.25, usage = "input", required = true },
  { pointer = "/usage/completion_tokens", cost_per_million = 10.00, usage = "output", required = true },
  { pointer = "/usage/prompt_tokens_details/cached_tokens", cost_per_million = -1.125 },  # $0.125 = $1.25 - $1.125
]
```

Peak vs off-peak rates are configured on the same entries. Set `timezone` on the provider so windows follow that provider's local clock:

```toml title="tensorzero.toml"
[models.qwen-plus.providers.dashscope]
type = "openai"
model_name = "qwen-plus"
timezone = "Asia/Shanghai"
currency = "CNY"
cost = [
  { pointer = "/usage/prompt_tokens", cost_per_million = 0.8, usage = "input", required = true,
    peak = { start = "08:00", end = "22:00", days = ["weekday"], cost_per_million = 2.0 } },
  { pointer = "/usage/completion_tokens", cost_per_million = 2.0, usage = "output", required = true,
    peak = { start = "08:00", end = "22:00", days = ["weekday"], cost_per_million = 6.0 } },
]
```

<ParamField body="pointer" type="string or array of JSON Pointers" required>

The `pointer` is a [JSON Pointer](https://datatracker.ietf.org/doc/html/rfc6901) into the provider's response.
A list is tried in order and the first pointer that is present wins (for example Chat Completions vs Responses usage paths).

You can use both `pointer_nonstreaming` and `pointer_streaming` instead of `pointer` if the usage format is different for streaming inferences. Those fields also accept a string or a list.

</ParamField>

<ParamField body="cost_per_million, cost_per_unit" type="float">

You can specify a flat rate using `cost_per_million` or `cost_per_unit`. The latter is useful for features like web search.
You can set negative cost values. This is useful for subtracting a cache discount from a parent token field (e.g. OpenAI includes cached tokens in `prompt_tokens`).
Do not set a flat rate on the same entry as `tiers`.

</ParamField>

<ParamField body="tiers" type="array of objects">

Token-length schedule. Each band has a `cost_per_million` or `cost_per_unit` rate and an optional exclusive `up_to` bound (tokens). Omit `up_to` on the last band for "and above".
`tier_mode` is `bucket` (default: the whole billed quantity uses one band, as in GLM-5.1) or `progressive` (each token is billed in the band it falls into).
`tier_by` is a pointer (or list) whose value selects the `bucket` band; defaults to this entry's billed pointer. Use it so output and cache rates follow input length.
Each band may also set `when = [{ pointer = "...", up_to = N }]` extra exclusive upper bounds (AND).

</ParamField>

<ParamField body="skip_if_pointer" type="string or array of JSON Pointers">

Skip this entry when any listed pointer resolves to a number greater than 0.
Useful for Omni-style billing where text output is free when audio output is present.

</ParamField>

<ParamField body="required" type="boolean">

You can mark an entry as `required`. If a provider does not report that field, the gateway will report the cost for that inference as `null` and log a warning.

</ParamField>

<ParamField body="usage" type='"input" | "output" | "cache_read" | "cache_write"'>

When set, the extracted pointer value is also written onto the corresponding TensorZero usage field (`input_tokens`, `output_tokens`, `provider_cache_read_input_tokens`, or `provider_cache_write_input_tokens`).
This lets you parse provider-specific usage JSON per `provider` + model instead of relying only on built-in provider parsers.
Omit `usage` to compute cost without changing token counts.

</ParamField>

<ParamField body="peak" type="object or array of objects">

Optional peak-hours rate(s). A single window or a list (for split peaks such as DeepSeek 09:00–12:00 and 14:00–18:00).
Outside every window the base `cost_per_million` / `cost_per_unit` or `tiers` schedule is used.
Peak windows themselves use a flat rate (not `tiers`).

- `start` / `end` — `HH:MM` or `HH:MM:SS`. `start` is inclusive, `end` is exclusive. If `start` is later than `end`, the window wraps midnight.
- `days` — `mon`…`sun`, `weekday`, and/or `weekend`. Empty (or omitted) means every day.
- `timezone` — IANA name such as `Asia/Shanghai`. Defaults to the provider-level `timezone`, or `UTC` if that is also unset.
- Peak rate — exactly one of `cost_per_million` or `cost_per_unit`.

</ParamField>

<ParamField body="currency (provider-level)" type="string">

ISO 4217 alphabetic code for this provider's `cost` / `batch_cost` rates (default `USD`). `RMB` is accepted as an alias for `CNY`.
Computed usage includes `currency` (OpenAI-compatible: `tensorzero_currency`). The gateway does not convert between currencies; mixed-currency totals are reported as `null`.

</ParamField>

<Accordion title="Example: Split peak windows (e.g. DeepSeek)">

DeepSeek bills two peak windows in Beijing time, with a lunch gap in between. Configure `peak` as an array.
Chat Completions and Responses expose cache/input at different paths; either use separate optional entries or a pointer list.

```toml title="tensorzero.toml"
[models.deepseek-chat.providers.deepseek]
type = "deepseek"
model_name = "deepseek-chat"
timezone = "Asia/Shanghai"
currency = "CNY"
cost = [
  { pointer = "/usage/prompt_cache_miss_tokens", cost_per_million = 1.5, usage = "input",
    peak = [
      { start = "09:00", end = "12:00", cost_per_million = 3.0 },
      { start = "14:00", end = "18:00", cost_per_million = 3.0 },
    ] },
  { pointer = "/usage/prompt_cache_hit_tokens", cost_per_million = 0.05, usage = "cache_read",
    peak = [
      { start = "09:00", end = "12:00", cost_per_million = 0.10 },
      { start = "14:00", end = "18:00", cost_per_million = 0.10 },
    ] },
  { pointer = "/usage/completion_tokens", cost_per_million = 4.5, usage = "output",
    peak = [
      { start = "09:00", end = "12:00", cost_per_million = 9.0 },
      { start = "14:00", end = "18:00", cost_per_million = 9.0 },
    ] },
]
```

</Accordion>

<Accordion title="Example: Input-length buckets (e.g. GLM-5.1)">

Zhipu GLM-5.1 selects one price band from the request's input length (`[0, 32k)` vs `[32k,)`).
Output and cache use the same input-length band via `tier_by`.
Rates below are yuan per million tokens as published on the provider pricing page; set `currency = "CNY"` so the UI and `usage.currency` show yuan instead of dollars.

```toml title="tensorzero.toml"
[models.glm-5.1.providers.zhipu]
type = "openai"
model_name = "glm-5.1"
currency = "CNY"
cost = [
  { pointer = "/usage/prompt_tokens", usage = "input", required = true,
    tiers = [
      { up_to = 32000, cost_per_million = 6 },
      { cost_per_million = 8 },
    ] },
  { pointer = "/usage/completion_tokens", usage = "output", required = true,
    tier_by = "/usage/prompt_tokens",
    tiers = [
      { up_to = 32000, cost_per_million = 24 },
      { cost_per_million = 28 },
    ] },
  { pointer = "/usage/prompt_tokens_details/cached_tokens", usage = "cache_read",
    tier_by = "/usage/prompt_tokens",
    tiers = [
      { up_to = 32000, cost_per_million = -4.7 },
      { cost_per_million = -6 },
    ] },
]
```

If the provider reports cache tokens separately from `prompt_tokens`, use the published cache rates (1.3 / 2) instead of negatives.

</Accordion>

<Accordion title="Example: Skip a line when another field is present (e.g. Omni audio output)">

```toml title="tensorzero.toml"
[models.qwen-omni.providers.dashscope]
type = "openai"
model_name = "qwen3-omni-flash"
cost = [
  { pointer = "/usage/prompt_tokens_details/text_tokens", cost_per_million = 0.8, usage = "input" },
  { pointer = "/usage/prompt_tokens_details/audio_tokens", cost_per_million = 3.2, usage = "input" },
  { pointer = "/usage/completion_tokens", cost_per_million = 2.0, usage = "output",
    skip_if_pointer = "/usage/completion_tokens_details/audio_tokens" },
  { pointer = "/usage/completion_tokens_details/audio_tokens", cost_per_million = 6.0, usage = "output" },
]
```

</Accordion>

See the [Configuration Reference](/gateway/configuration-reference/) for more details.

<Warning>

Make sure to understand how different model providers report usage data.
For example, OpenAI includes cached tokens in `prompt_tokens`, but Anthropic doesn't include them in `input_tokens`.

</Warning>

<Note>

Cost tracking is not available for short-hand models (e.g. `openai::gpt-5`).
Instead, you must explicitly configure the model and the model provider in your configuration, as above.

</Note>

### Configure cost tracking for batch inference

You can configure cost for batch inference with `batch_cost` alongside the `cost` field:

```toml title="tensorzero.toml"
[models.gpt-5.providers.openai]
# ...
batch_cost = [
  { pointer = "/usage/prompt_tokens", cost_per_million = 0.625, required = true },
  { pointer = "/usage/completion_tokens", cost_per_million = 5.00, required = true },
  { pointer = "/usage/prompt_tokens_details/cached_tokens", cost_per_million = -0.5625 },  # $0.0625 = $0.625 - $0.5625
]
```

### Configure cost tracking for embedding models

You can also configure `cost` for embedding model providers:

```toml title="tensorzero.toml"
[embedding_models.text-embedding-3-small.providers.openai]
type = "openai"
model_name = "text-embedding-3-small"
cost = [
  { pointer = "/usage/total_tokens", cost_per_million = 0.02, required = true },
]
```

### Run an inference with cost tracking

Once you've configured `cost` for a model provider, inference responses will include `cost` (TensorZero SDK) or `tensorzero_cost` (OpenAI SDK) in the `usage` object:

```python
ChatCompletion(
    # ...
    usage=CompletionUsage(
        # ...
        tensorzero_cost=0.0073075 # [!code ++]
        # ...
    ),
    # ...
)
```

You can also browse cost data for individual inferences as well as aggregated cost statistics per model provider in the TensorZero UI.
You can also [enforce custom rate limits](/operations/enforce-custom-rate-limits) based on cost.
